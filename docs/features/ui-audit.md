# Layout and copy audit

`ui-audit` fails a QAE run whose browser measured a layout or copy defect on the site under test: controls in one row that do not line up, bordered controls touching each other or their container's edge, a spinner off its button's middle, a count, initials or check mark off its circle's middle, a wall of text or a very long sentence, a raw value such as `in_review` or `undefined`, text or a value its box cuts off, and two buttons in one dialog or form whose names a person cannot tell apart ("Send invite" beside "Send invite"), and a short label in a pill, badge, button or tab that takes two lines (a margin pill with its arrow above "12.5%"), a table that scrolls sideways while the layout around it has room for all of it, page bands stacked in one column whose content starts a different distance from the edge they share (a header 32px in above a toolbar 16px in), a field too small for what it asks (a reason box 90px wide in a table row), and an icon or spinner whose ink sits off the middle of its button (a spinner tilted in 3D that a flex box centers by its box, not its ink). A finding blocks only when the pull request adds the text of the element it names or of its neighbour; one on a screen the base already had is listed without blocking, for a cleanup pull request to work from. The QAE explorer never judges these: the harness's layout hook measures every page the explorer opens, at every width it uses and every other width the run asks for (the width captures resize the page to each after each of the explorer's screenshots: [harnesses/qae/README.md](../../harnesses/qae/README.md#viewports-themes-and-what-a-criterion-does-not-say)), from rendered rectangles and computed styles (and, for where an icon sits in its button, screenshots of the button), and writes `ui-audit.jsonl` beside the run's other evidence. A screenshot diff cannot catch them, because a baseline that already has the defect passes forever.

The same audit runs from a shell before a push: `node actions/qae-browser/ui-audit.js [--width N]... [--storage-state FILE] [--channel chrome] URL...` prints one line per finding at 1280 and 375 pixels by default and exits 1 when there is one.

## Reach

Add a line to the QAE manifest (`.vibe-verifier-qae`), after `qae-artifacts`:

    ui-audit --artifacts qae-artifacts --site-file qae-inputs/site-url --soak

`--soak` reports without failing (in the job log and under Not yet blocking in the QA review); drop it once ten pull requests in a row raised no false finding. `--all` makes a finding on the base's screens block too. A second line with `--rules R` and no `--soak` blocks on one rule while the rest soak. `--rules R[,R...]` judges only some rules, and `--allow REGEX` (repeatable) skips a finding whose element path or text matches, for a design the repository chose. Both QAE lanes load the hook: `harnesses/qae/explore.yml` passes `actions/qae-browser`'s `ui-audit` output as a second `--init-page`, and `actions/qae-codex` passes the file itself. A repository with its own copy of `explore.yml` needs that second `--init-page` in its copy before it adds the manifest line: without the hook there is no record, and the gate cannot run.

## Gotchas

- A run with no record to judge (a pull request that declares `- None:` runs no explorer) passes before the site file is read: the verify job writes that file empty then.
- The rules and their thresholds are in the header of `actions/qae-browser/ui-audit-page.js`. Each was checked against two subscribed apps' real screens (a quote builder, lists, dashboards, a people page, an add-user dialog, 2026-11-03) and narrowed where it flagged a design: a pill track with even padding, a tab toggle whose idle tab has no border, a map's zoom bar, a header button beside a search field in the page below, a list row with only a divider under it. A sidebar's Collapse button beside a page's Save prices was flagged on a subscribed app's record page (2026-11-08) because the app shell lays its sidebar and main region out in one grid: a row whose two controls each sit in a page region of their own under it (aside, nav, main, header, footer or their roles) is not judged. A header's nav beside its Account button, one control in a region and one not, is still a row. Five more of its findings there were columns, not cells: an open form (a reason field over its own Exclude and Cancel) beside a Correct button (two), and a two-column form whose columns each stack fields (three). A control whose item in the row stacks another control above or below it is not lined up with the next (`row-stagger`, `row-height`); a hint or label under a field is not a control, so a button pulled off its field by the field's hint still counts.
- A badge's mark is measured by its ink, not its line box: a digit has no descender, so text centered by its line box (`line-height` equal to the height, or flex centering) sits high when the font's ascent and descent are uneven. A CSS-drawn tick (a `::before` or `::after` with two borders, rotated) is measured through its transform. Checked on a subscribed app's notification count and request tab badge, with its own font (each 1.1 to 1.4px high), and its circle checks (2026-11-04).
- `duplicate-name` compares the buttons a person can press (visible, not disabled) inside one dialog, else one form: equal names, or one name the other with words added ("Create account", "Create account now"). A choice that a submit button acts on is a radio, which it does not judge. Buttons in different rows of one list or table (each row's Remove) are told apart by their row. It came from a subscribed app's add-someone dialog (2026-11-04), which showed a pressed "Send invite" choice beside the "Send invite" submit, and whose own test picked them apart with `.first()` and `.last()`.
- "The pull request adds it" is copy-audit's test (four consecutive words, or a whole short label, on an added line of `git diff <base>...HEAD`), applied to the element's text and its neighbour's. A defect a pull request causes on an existing label (a padding change that makes two old buttons touch) and one on an element with no text are listed, not blocked: nothing in the diff names them.
- A spinner shows only while something loads, so the hook also measures the moment a button gains an element whose class names a spinner or loader, or a `role=progressbar`.
- A dialog opens with no load or navigation, so the hook also measures half a second after a dialog, alert or status message appears. At each measure it also writes the page's copy record, `copy.jsonl`, for the [copy audit](copy-audit.md).
- The record holds what the page shows, as the screenshots do, never a password field's value.
- A run with step logs and no record cannot run: the hook was not loaded, and a clean soak and a broken one would otherwise look the same.
- `wrapped-label` judges labels of four words and 24 characters or fewer: a sentence in a pill may wrap. In a pill or badge (boxed, every corner rounded to half its height) an icon counts as part of the label, so an arrow above its percentage is two lines; in a button or tab it does not, so an icon placed above the label by design is not flagged, but the label's own text wrapping is. It came from a subscribed app's quote panel (2026-11-06), whose margin pill showed its arrow above "12.5%" in a card with room for both. Run on that screen, the rule found it at 1280 and 375 pixels. Text only a screen reader reads (a clipped `.sr-only` span) is no line, and an icon font's ligature ("add") above a button's label counts as its icon.
- `table-scroll` measures room, not width: a table scrolls sideways (by more than 8px) while some box around it, up to its dialog, else the page's main region (`main` or `role=main`), else the body, has unused width beside it at least as wide as what the table hides. A visible box beside it at the same height (a summary card, also through a `display:contents` wrapper) is not room, nor is the navigation beside the main region or the page behind a dialog's overlay, and a box that scrolls for something else beside a table that fits is not judged, so a wide table on a phone and a table beside a card that fills the row are not flagged. Room often appears only at wide windows: a subscribed app's quote page capped its two-column grid at 1180px, so at 1920 and 2560 pixels its lane table scrolled beside 460 and 1100px of empty page, while at 1280 the summary card filled the row (2026-11-06). The explorer may never use a window that wide, so the hook measures this rule itself at 1920: once per page, when the explorer's window is narrower, it loads the page in a window of its own, signed in as the explorer is (a new browser context from the explorer's storage state, closed after), and records table-scroll's findings at that width. The explorer's tab list never shows that window, and no repository has to add a width. It is a second load of the same address, as a reload is, and a page that will not load a second time is measured at the explorer's widths alone. On the subscribed app's quote page, walked at 1280 and signed in, it found the lane table at 1920.
- `uneven-gutter` judges only the page's own columns: a box as wide as the window, or as the main region, at its left edge. Its bands are the children that span it and stand 24px or taller, compared one below the next (layers laid over each other are not). A band's left edge is where its lines of text start (the content edge of the block that lays them out, so a first-line indent does not move it) or where its images, controls or drawn boxes start; its right edge is where its boxes and controls end, never its text, since left-aligned lines end where their words do. A box as wide as the band (a divider, a full-bleed strip, a chart) is structure, and what an svg draws inside itself, a box that is hidden or out of the flow, and anything placed by centering (a row its flex or grid container centers or spreads, an inline logo in a centered line, and text a block centers or sets right) are not where content sits; a button in a right-aligned row still ends at the right gutter, and a column centered at a fixed size (both side margins written `auto`, a width or max-width in px) is centered too, while a container held in by a relative width (`calc(100% - 32px)`) or by margins in px is a gutter. Two stacked bands whose edges sit more than 4px apart, both within 48px of the edge, are a finding; an inset past 48px is a layout choice (an indented note), a card (a box with rounded corners) holds its own padding and is not a band, and a table's rows are not bands. It came from two subscribed apps (2026-11-06): a rate page whose header started 32px in above a toolbar and table 16px in, and a dashboard whose bot strip started 10px in under a header 18px in. Run on six pages of one app at 1280 and 390, it found the rate page alone, and on five other subscribers' public pages it found nothing. One of those sites keeps its footer in a column centered at a fixed width, which lands 32px in under a card 22px in at 390: that column is read as centered, so it is not flagged.
- `cramped-field` judges the fields a person types into (text, search, email, url and tel inputs, and textareas; not read-only or disabled ones, whose value cut off is `clipped-value`'s). A field is cramped when what it holds is wider than it shows (its `scrollWidth` past its `clientWidth`), whatever it asks: what was typed is already out of view. A box already as wide as it can be has no room to show more, so a long value in it is not judged: it fills its container's content box, and so does each container up to the main region (or the body), whatever their padding or side margins in px; a box fixed to the window, such as a dialog, fills it when it leaves no more than 48px on each side. On a phone every form field is full width, and a long name cut off there is normal; a box in a table cell, a grid column, a sidebar, a dialog narrower than the window, or a box centered at a fixed size (its side margins written `auto`) stops short and is still judged. One that asks for free text is cramped when it shows fewer than 30 average characters of its own font (measured on an everyday sentence, so a 13px font and a 16px one each get their own width), or, a textarea, fewer than two lines. 30 characters is five words of everyday English, so a person can read back the phrase they are typing: the reason field that set this off shows 16, and a subscribed app's contact form shows 36 in its message box at a phone's width and 99 at 1280. A field asks for free text when its accessible name, labels, title or placeholder (or, with none, its name or id split into words) say reason, note, comment, description, describe, explain, why, message, details, feedback, summary, instructions, memo or remarks, and say no short answer beside it (name, title, subject, code, number, id, email, phone, city, zip, search, quantity, amount, price, date, sku): "Reason code" and "Search notes" are short answers. Only a text or search input, or a textarea, takes a sentence: a field with a number or address keyboard (`inputmode` numeric, decimal, tel, email or url) never does. A `maxlength` the field can show is never cramped, and a textarea an autosize script sizes (its height set inline) or that CSS sizes to its content (`field-sizing: content`) grows past one line as it is typed in. A finding names the field's label too (a `<label>` or the `aria-labelledby` element), so a pull request that adds the label is told; one on a field with no label, `aria-label`, value or placeholder shows no text and is listed without blocking. What a person typed is in a field's value, which no mutation shows, so the hook also measures 0.6 seconds after the explorer last typed into a field or ticked a box, and half a second after a text field appears. It came from a subscribed app's quote table (2026-11-07), whose "No bid" box showed a reason input about 90px wide, so "No stock" already scrolled its start out of view. On a signed-in preview of that app (eight pages at 1280 and 375) it found one value cut off by its field, seeded data two digits too long for a profile name, at 1280 where the box takes a third of its row (at 375 it was flagged too until the full-width skip, 2026-11-09); on twelve public pages of the subscribed apps (sign-in, marketing and contact pages) it found nothing.
- `icon-off-center` judges a button, `role=button`, tab, radio segment, or a link or label styled as a button, whose only content is one mark: an svg, img or canvas, a spinner, an icon font's glyph, an empty box an icon is drawn on, or layers of one drawing, through wrappers that draw nothing; text only a screen reader reads, or a label kept at opacity 0 behind a spinner, is not content. It measures ink, not boxes, because a CSS-drawn mark or a spinner tilted in 3D draws away from the box the DOM reports. So it reads pixels: at each measure the hook screenshots up to four such controls, wholly in the window and under nothing, three frames 120ms apart, and finds the box of the pixels that differ from the colour most of the control shows, inside its border and its rounded corners. A finding needs every frame's ink more than 1.5px off the content box's middle, on either axis: a spinner turns, so a symmetric one caught between frames, or a ring with a gap, passes, while a mark drawn lopsided in every frame does not. Each control is sampled once per page, width and mark, so an icon swapped for a spinner is sampled again. The middle is the content box's, so padding set on one side to center an icon by eye (a play triangle) is not a defect. It does not judge an icon beside a label, a control with no box a person sees (a box shadow counts only when it draws; Tailwind's zero-size ring shadows do not), a second mark (a bell's dot, a drawn caret), an icon whose ink reaches within 2px of its button's edge (a bar along a tab's foot, or an icon that fills its button, cannot be told from the box), a control under a menu or dialog, or one partly out of the window. A spinner that took its button's label shows no text, so its finding is listed and blocks only under `--all`, as other findings on an element with no text do. It came from a subscribed app's pending button (2026-11-07), whose label became a spinner of three orbits, each one border edge of a circle tilted in 3D: inline-flex centered the spinner's box, but its ink sat right of the middle. Measured: a static frame of three such orbits at 16px sits 1.0 to 2.5px off its box's middle, by its tilts; the same orbits turning about their own centres swing between 0.5 and 3px in both directions, so the rule flags a spinner only while it is lopsided in every frame it samples. On a signed-in preview of that app it judged the header's two icon buttons on every page, each within 0.5px. The twelve public pages hold no icon-only button with a box (a password field's eye has none).
- `field-stagger` compares the first field of each cell of a grid or flex row, so it judges the row a form lays out, not a page's columns: a cell whose field follows a visible heading in that cell (an `h1` to `h6` or `role=heading`) is a section of the page and is compared with no other cell, since a form cell's caption is a label. It came from a subscribed app's results page (2026-11-08), a two-column dashboard whose columns are stacks of titled cards: the rule compared a select one card down the left column with a part picker in the right column's first card and reported "fields in one row start up to 1026px apart". After the change that page is clean at 1280, 1920 and 375 pixels, and the fixture's form row whose hint pushes one field down is still flagged. A form row whose cells use headings as their captions is not judged.
- `boxed` (which the touching, edge, glyph, wrapped-label and uneven-gutter rules also use) counts a box shadow only when one of its layers has a colour and an offset, blur or spread: Tailwind's ring and shadow utilities leave `0 0 #0000` layers, and ring colours at 0px, on elements that draw no shadow.
